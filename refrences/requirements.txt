I’m building Mini RV Parks, an RV-only booking website using a near copy of Outdoorsy + Airbnb interface patterns (search → list/map results → listing detail → request-to-book), but simpler and cleaner. The beta includes two tabs: Stays and Storage.

This is not general camping (no tents, no cabins, no boondocking). It’s built for RV pads with clear hookups, strong photos, and a smooth request-to-book flow.
A) Plain-English overview (read this first)
1) Stays (nightly)

Guests should be able to:

    search by destination + radius + dates

    filter by hookups + pull-through

    view listing pages

    request to book

    pay only after the host accepts

Hosts (landowners) should be able to:

    create a listing quickly

    upload photos (critical)

    set availability (available/blocked)

    set nightly price

    accept/decline requests

2) Storage (monthly)

Guests should be able to:

    search storage by destination + radius + move-in date

    view storage listing pages

    request storage

    pay only after the host accepts (deposit + first month)

Hosts should be able to:

    create a storage listing quickly

    upload photos (critical)

    toggle availability (available/unavailable)

    set monthly price + deposit

    accept/decline storage requests

Admin (me) controls quality

I will:

    approve listings before they go live

    approve beta guests (grassroots model: apply → I call → I approve)

    mark listings “Verified” in beta (meaning I checked location + photos)

Beta launch target: May 1
Inventory target before letting guests request: 50 approved, LIVE listings

6) Booking system rules (exact)
STAYS objects

Booking Request (pre-payment)
Statuses: REQUESTED / ACCEPTED / DECLINED / EXPIRED / CANCELLED_BY_GUEST / CANCELLED_BY_HOST

Rules:

    guest creates REQUESTED

    host ACCEPTS or DECLINES

    on ACCEPT: set expires_at = now + 24h

    while ACCEPTED: dates are soft-held (unavailable to other requests)

    if guest pays → create booking CONFIRMED

    if unpaid by expires_at → request EXPIRED and soft-hold removed

Booking (post-payment)
Statuses: CONFIRMED / CANCELLED / COMPLETED
STORAGE objects

Storage Request (pre-payment)
Statuses: same as above

Rules:

    guest creates REQUESTED with move-in date + months (default 1)

    host ACCEPTS or DECLINES

    on ACCEPT: set expires_at = now + 24h and soft-hold the slot

    if guest pays deposit + first month → create Storage Contract ACTIVE and set listing unavailable

    if unpaid by expires_at → EXPIRED and slot reopens

Storage Contract (post-payment)
Statuses: ACTIVE / CANCELLED / ENDED
Beta: no recurring billing. Contract records start date and monthly price snapshot.
